# GEMINI Project Analysis: Tyr

## Project Overview

This is a C++ project that builds a Dynamic Link Library (DLL) named `Tyr`. Based on the included headers and code structure, this project is a game modification (cheat/hack) for a game built on Unreal Engine, likely named "Tyr" as well.

The core functionality revolves around an **ESP (Extra Sensory Perception)** feature, which renders information about in-game entities directly onto the screen. The entry point (`dllmain.cpp`) hooks into the game's rendering loop (`DrawTransition`) to execute its own drawing function (`Loop` in `ESP.hpp`) on each frame.

The project includes a comprehensive SDK (Software Development Kit) for the game, generated by the "Dumper-7" tool, which provides access to the game's internal classes and functions.

**Key Technologies:**
- **Language:** C++ (using `stdcpplatest` standard)
- **Platform:** Windows (x64)
- **Target Engine:** Unreal Engine
- **Build System:** MSBuild (Visual Studio 2022)

## Building and Running

### Building the Project

This is a Visual Studio solution. To build the project, you will need:
- Visual Studio 2022 with the "Desktop development with C++" workload installed.

1.  Open the `Tyr.sln` file in Visual Studio.
2.  Set the build configuration to **Release** and the platform to **x64**.
3.  From the menu, select `Build > Build Solution`.

This will produce `Tyr.dll` in the `x64/Release` directory.

## Development Conventions

*   **Coding Style:** The code generally follows standard C++ conventions. It heavily utilizes the naming conventions from the Unreal Engine SDK (e.g., `A` prefix for Actors like `APlayerController`, `U` prefix for UObjects like `UCanvas`).
*   **Game Interaction:** The primary method of interacting with the game is through VTable hooking. The `HookVftFunction` in `dllmain.cpp` is a utility for this purpose, allowing the replacement of game engine functions with custom ones at runtime.
*   **Dependencies:** The project is self-contained and relies on the Windows API and the provided game SDK. No external libraries are used.
*   **Headers:** `SDK.hpp` is the primary include file that brings in the entire game's SDK. For faster compilation, it is recommended to include specific headers from the `SDK/` directory instead.
